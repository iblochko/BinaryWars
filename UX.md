# Лабораторная работа №6 — «Улучшение UX»

**Проект:** BinaryWars (Godot 4)  
**Репозиторий:** https://github.com/iblochko/BinaryWars

---

## 1. Описание проекта

BinaryWars — пошаговая тактическая игра на движке Godot 4. Два игрока управляют фракциями **Zerrior** и **Onerrior** на изометрической карте, поочерёдно перемещая юниты, атакуя противника и захватывая стратегические объекты. Игровой процесс включает управление юнитами, зданиями-казармами и системой ходов.

## 2. Оценка ПО по атрибутам качества Usability (ISO/IEC 25010:2011)

| Атрибут | Оценка | Обоснование |
|---|---|---|
| Распознаваемость соответствия | Средняя → Высокая | После добавления главного меню и туториала пользователь сразу понимает назначение приложения. До правок — игра запускалась сразу в бой без контекста. |
| Обучаемость | Низкая → Средняя | Добавлено окно туториала с описанием механик. Без него новый игрок не знал правил управления и целей игры. |
| Используемость (операбельность) | Низкая → Высокая | Реализованы хоткеи (A — атака, D — защита, Space — пропуск, T — конец хода, Escape — закрыть панель), управление камерой мышью и клавишами, здания с многоклеточным размером. |
| Защита от ошибок пользователя | Низкая → Средняя | Добавлено ограничение на выход камеры за пределы карты (`bounds_enabled`). Кнопки деактивируются при отсутствии допустимых действий. |
| Эстетика GUI | Низкая → Средняя | Добавлены главное меню с кнопками и туториал-попап. Панель действий отображает иконки и хоткеи прямо на кнопках. Полоска здоровья у зданий меняет цвет. |
| Доступность | Низкая | Клавиатурные хоткеи облегчают управление. Полноценная поддержка accessibility (экранный диктор, масштабирование) не реализована — задел на будущее. |

## 3. Выбранные пути улучшения UX и обоснование

Анализ исходного состояния проекта выявил следующие проблемы:

- Отсутствие точки входа — игра сразу запускала боевую сцену без контекста
- Отсутствие обучающего материала — пользователь не мог узнать правила без чтения исходного кода
- Неудобное управление камерой — только стрелки, без мыши, без ограничения границ карты
- Отсутствие хоткеев — все действия требовали нажатия кнопок мышью
- Здания не имели игровой логики — не занимали клеток, не обрабатывали клики, не имели HP

| Улучшение | UX-атрибут | Обоснование |
|---|---|---|
| Главное меню | Распознаваемость, Эстетика | Стандартная точка входа. Пользователь ориентируется и выбирает действие. |
| Окно туториала | Обучаемость | Снижает порог вхождения — пользователь узнаёт правила без внешней документации. |
| Камера на мыши (edge scroll) | Операбельность | Стандарт в стратегических играх. Интуитивное управление без переключения на клавиатуру. |
| Ограничение камеры на карте | Защита от ошибок | Пользователь не теряет игровое поле из виду. |
| Горячие клавиши | Операбельность | Ускоряют взаимодействие, соответствуют ожиданиям жанра. |
| Здания (Barracks) | Операбельность, Эстетика | Многоклеточный размер, HP, производство юнитов, визуальная обратная связь. |

## 4. Проведённые улучшения: «До» и «После»

---

### 4.1 Главное меню (MainMenu)

**До:**  
При запуске приложения игра немедленно загружала боевую сцену (`Game.tscn`). Пользователь не имел возможности подготовиться, прочитать правила или выйти стандартным образом. Отсутствовала какая-либо навигация.

**После:**  
Реализована сцена `scenes/Menu/MainMenu.tscn` со скриптом `scripts/Menu/MainMenu.gd`. Меню содержит три кнопки:

- **«Начать игру»** — загружает `Game.tscn`
- **«Туториал»** — открывает всплывающее окно с инструкциями
- **«Выход»** — завершает приложение

```gdscript
# MainMenu.gd
func _ready():
    start_button.pressed.connect(_on_start_pressed)
    tutorial_button.pressed.connect(_on_tutorial_pressed)
    exit_button.pressed.connect(_on_exit_pressed)

func _on_start_pressed():
    var game_scene = load("res://scenes/game/Game.tscn")
    get_tree().change_scene_to_packed(game_scene)

func _on_exit_pressed():
    get_tree().quit()
```

### 4.2 Окно туториала (TutorialPopup)

**До:**  
Правила игры не были представлены в интерфейсе. Пользователь должен был самостоятельно выяснять управление методом проб и ошибок.

**После:**  
Создана сцена `scenes/Menu/TutorialPopup.tscn` со скриптом `scripts/Menu/TutorialPopup.gd`. Попап открывается из главного меню, закрывается кнопкой «Закрыть» или клавишей **Escape**. Содержит описание управления, целей игры и доступных действий.

```gdscript
# TutorialPopup.gd
func _input(event):
    if event is InputEventKey and event.pressed:
        if event.keycode == KEY_ESCAPE and visible:
            hide_popup()
```

### 4.3 Управление камерой мышью (Edge Scroll)

**До:**  
Камера перемещалась исключительно стрелками клавиатуры. Пользователь был вынужден переключать руку с мыши на клавиатуру, что нарушало игровой поток.

**После:**  
В `CameraManager.gd` реализован **edge scroll** — при приближении курсора к краю экрана камера плавно смещается в соответствующую сторону. Параметры настраиваются через `@export`-переменные:

| Параметр | Описание |
|---|---|
| `edge_scroll_enabled` | Включение/отключение функции |
| `edge_scroll_margin` | Пороговое расстояние от края (px) |
| `edge_scroll_speed` | Скорость прокрутки |

```gdscript
# CameraManager.gd
func _get_edge_scroll_direction() -> Vector2:
    var mouse_pos = get_viewport().get_mouse_position()
    var viewport_size = get_viewport().get_visible_rect().size
    var direction = Vector2.ZERO

    if mouse_pos.x < edge_scroll_margin:        direction.x -= 1
    if mouse_pos.x > viewport_size.x - edge_scroll_margin: direction.x += 1
    if mouse_pos.y < edge_scroll_margin:        direction.y -= 1
    if mouse_pos.y > viewport_size.y - edge_scroll_margin: direction.y += 1

    return direction
```

Скорость нарастает плавно через `move_toward()` — рывков при начале движения нет.

### 4.4 Ограничение выхода камеры за границы карты

**До:**  
Камера могла свободно уходить за пределы игровой карты, отображая пустое пространство. Пользователь терял ориентацию.

**После:**  
Реализована функция `_limit_position()`, которая вычисляет допустимый диапазон позиций с учётом текущего масштаба (`zoom`) и размеров карты. Корректно обрабатывается случай, когда viewport больше карты.

```gdscript
# CameraManager.gd
func _limit_position():
    var viewport_size = get_viewport().get_visible_rect().size
    var half_visible_width  = (viewport_size.x / zoom.x) / 2
    var half_visible_height = (viewport_size.y / zoom.y) / 2

    var x_limit = max(0, map_width  / 2 - half_visible_width)
    var y_limit = max(0, map_height / 2 - half_visible_height)

    position.x = clamp(position.x, -x_limit, x_limit)
    position.y = clamp(position.y, -y_limit, y_limit)
```

Включается флагом `bounds_enabled = true`.

### 4.5 Горячие клавиши (Hotkeys)

**До:**  
Все игровые действия выполнялись только мышью через панель действий. Отсутствие хоткеев замедляло игровой процесс.

**После:**  
Реализованы горячие клавиши в двух компонентах.

**ActionPanel.gd** — действия с юнитом/зданием:

| Клавиша | Действие |
|---|---|
| `A` | Атаковать / Произвести юнита (казарма) |
| `D` | Защитная стойка |
| `Space` | Пропуск хода |
| `Escape` | Закрыть панель |

**TurnUI.gd** — управление ходами:

| Клавиша | Действие |
|---|---|
| `T` | Завершить текущий ход |

```gdscript
# ActionPanel.gd
func _input(event):
    if not is_visible_panel:
        return
    if event is InputEventKey and event.pressed:
        var key = OS.get_keycode_string(event.keycode).to_lower()
        if   key == hotkey_attack:  _on_attack_pressed()
        elif key == hotkey_defend:  _on_defend_pressed()
        elif key == hotkey_action:  _on_action_pressed()
        elif key == hotkey_close:   _on_close_pressed()
        get_viewport().set_input_as_handled()
```

Хоткеи работают **только при открытой панели** (`is_visible_panel`), что предотвращает случайные срабатывания. Назначения клавиш отображаются прямо на кнопках: `⚔️ Attack [A]`.

### 4.6 Поддержка зданий (Buildings / Barracks)

**До:**  
Здания на карте были визуальными объектами без логики: не занимали клеток сетки, не обрабатывали клики, не имели HP.

**После:**  
Реализована иерархия классов:

- **`BaseBuilding`** (`Building.gd`) — базовый класс: HP, размер (`building_size`), фракция, регистрация на карте, полоска здоровья
- **`BaseBarracks`** (`Barracks.gd`) — производство юнитов через `produce_unit()`

Ключевые UX-улучшения:

- **Многоклеточное размещение** — казарма 3×3 занимает 9 клеток сетки, корректно блокируя проход юнитов
- **Визуальная обратная связь при выделении** — здание подсвечивается зелёным и увеличивается на 10%
- **Полоска HP** — отображается при выделении, меняет цвет: зелёный (>60%), жёлтый (>30%), красный (≤30%)
- **Текстуры по фракции** — автоматически применяется текстура соответствующего игрока
- **Интеграция с ActionPanel** — при выделении здания открывается панель с действием «Произвести юнита»

```gdscript
# Building.gd
func _calculate_occupied_cells():
    occupied_cells.clear()
    var half_w = floor(building_size.x / 2.0)
    var half_h = floor(building_size.y / 2.0)
    for x in range(-half_w, half_w + 1):
        for y in range(-half_h, half_h + 1):
            occupied_cells.append(current_cell + Vector2i(x, y))
```

## 6. Выводы

В ходе лабораторной работы проведена оценка BinaryWars по шести атрибутам группы Usability стандарта ISO/IEC 25010:2011. Выявленные недостатки устранены путём реализации шести улучшений.

**Достигнутые результаты:**

- Игра получила стандартную точку входа (главное меню), соответствующую пользовательским ожиданиям
- Новый пользователь может изучить правила через встроенный туториал без обращения к внешней документации
- Управление стало значительно удобнее благодаря edge scroll и полному набору горячих клавиш
- Реализована защита от ошибок — камера не уходит за пределы карты, недопустимые действия заблокированы
- Система зданий обогатила игровые механики и обеспечила понятную визуальную обратную связь

**Направления для дальнейших улучшений:**

- Полноценная поддержка accessibility (масштабирование интерфейса, экранный диктор)
- Анимированные переходы между состояниями UI
- Звуковая обратная связь на действия пользователя
- Локализация интерфейса
